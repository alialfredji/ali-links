# Ali Links

Build a fast personal link page from the Astro Brand Starter. The public page keeps one shared profile, social set, and link list in the Flat style. A review-only `?preview=1` mode exposes Flat and Terminal for comparison. Light and dark theme choices remain public and independent from the preview style.

<Callout id="plan-recommendation" tone="decision">
  Keep the starter's static Astro architecture and replace the localized starter
  routes with one focused profile route at `/`. Store profile content in one
  typed configuration file, render it with semantic links, and express four
  review combinations through CSS tokens and two data attributes on the document
  root. Outside `?preview=1`, the style is always Flat.
</Callout>

The theme bootstrap runs inline in the document head so a returning visitor does not see a light-mode flash. With JavaScript disabled, Flat remains the style fallback and the CSS media query follows the system color preference. Outside `?preview=1`, stored Terminal choices are ignored so visitors always receive the approved Flat direction.

## Ordered implementation

1. Rename the cloned package and retain the starter repository as the `upstream` remote. Do not create a public origin or deploy during this slice.
2. Add `profile.ts`, the monochrome profile placeholder, and the build-time Simple Icons dependency.
3. Replace the current home composition with `ProfileLinks.astro`, `SocialLinks.astro`, `LinkList.astro`, and `StyleControls.astro`.
4. Refactor `tokens.css` into shared geometry, light and dark colors, and the Flat and Terminal overrides. Keep all controls sharp with one documented radius rule.
5. Add the preference bootstrap and click handling. Keep the theme toggle public, reveal the style selector only with `?preview=1`, update `aria-pressed` immediately, persist valid preview selections, and never block navigation.
6. Update `/` and metadata to describe a personal profile page, then remove the starter's localized routes and language gateway.
7. Add pure preference tests, run the full starter validation command, and inspect the production build at mobile and desktop widths.

## Responsive and interaction rules

- Mobile is the source layout. Use `padding-inline: clamp(1rem, 5vw, 1.5rem)` and a strict single column below 768px.
- Desktop changes only the outer breathing room. The profile column remains at `max-inline-size: 40rem` and never stretches into a landing-page layout.
- Link rows are at least 48px high, span the full column, and keep labels on one line.
- All interactive radii are zero and both styles use one-pixel lines.
- Hover communicates destination affordance by inverting ink and paper. Press communicates activation through a one-pixel translation.
- The initial reveal may stagger the profile and link rows once. `prefers-reduced-motion: reduce` removes entry and translation effects.
- Focus-visible outlines remain distinct from borders in both themes. Style and theme controls use native buttons with `aria-pressed`.
- The profile image reserves its final dimensions to avoid layout shift. The eventual real image replaces the local placeholder through Astro's image pipeline.

## Scope boundary

This first slice includes the new local project, one root profile route, placeholder content and image, Flat as the public style, Terminal as a `?preview=1` comparison, public light and dark themes, responsive layout, metadata updates, tests, and local verification. It defers final copy, real destinations, final portrait, analytics, contact forms, a CMS, additional pages, deployment, and a new GitHub origin.
